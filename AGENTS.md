# Participation architecture
- Coordinate opt-in speech through the global accessibility controls, with dedicated dictation buttons inside dialogs because modal focus must remain within Radix; never intercept browser zoom or auto-start microphones.
- Use the shared AccessibleMedia player for caption preferences, local WebVTT loading and truthful text-alternative availability; descriptions are not transcripts.
- Keep accessibility copy in the shared translation hook's dedicated dictionary and let Radix manage menu and dialog focus; route focus management only targets primary content.
- Store About people in a dedicated collection with admin-only writes and published-only public reads; keep portraits private and grant reads through published profile visibility so drafts stay private.
- Keep About profile labels in the shared translation hook's dedicated dictionary so public and admin screens use the same language.
- Auth-backed access queries must be keyed by the current context user and wait for auth initialization; stale signed-out or prior-account checks must not block a new sign-in.
- Auth listeners remain synchronous and startup reads cannot override newer events; this prevents lock stalls and stale account state.
- Automatic onboarding opens only on the home page so direct participation links stay usable.
- Store consultation learning materials in one parent-scoped table and a private storage bucket; inherited parent visibility prevents exposing private attachments.
- Calculate ballot totals in database triggers and expose individual ballots only to their owners; public UI reads aggregate counts rather than identifiable votes.
- Keep participation copy in a dedicated dictionary consumed by the shared translation hook; new participation screens follow existing language selection.
- Use plain-text downloadable reading packs and opt-in media loading; weak connections should not require downloading images or video to understand a consultation.- Sealed-result polls tally into a private table and reveal counts only through a server function after close; never write their counts to the public poll row.
- Save sign-in expiry on the device's own clock via a storage wrapper installed before the app starts; sign-in must never depend on the device's date and time.
